# Hosted browsers: is anything better or cheaper than Browserbase for Circle?

Researched 2026-10-19 from pricing pages, docs, GitHub and the npm registry, plus three live probes from this machine against the Browserbase account in `.env`. The simular.ai "Browserbase alternatives" page was used only as a lead list; every claim below comes from the vendor's own site unless marked [unverified].

## First finding: the timeout is ours, not Browserbase's

`connect.usw2.browserbase.com` is reachable and fast from this machine. What fails is `playwright-core` under Bun 1.3.14.

- Raw `WebSocket(connectUrl)` from Bun: open and a `Browser.getVersion` reply in 0.57 s (Chrome 155).
- `chromium.connectOverCDP(connectUrl)` from Bun 1.3.14 with playwright-core 1.64.1: `Timeout 60000ms exceeded`.
- The same script under Node 23: connected in 0.82 s, `example.com` loaded in 2.1 s total.
- Bun + connectOverCDP against a local headless Chrome on `ws://127.0.0.1` also times out, so it is not TLS or the network.
- Known Bun bug: Playwright's bundled `ws` handshake needs the `'upgrade'` event on `http.ClientRequest`, which Bun did not emit. oven-sh/bun #9911, #28450 and #32526 ("works on Node") are closed by the `node:http` client rewrite #31587, merged 2026-06-17. Bun 1.3.14 was released 2026-05-13, before the fix; 1.4.0 (2026-08-20) and later carry it.

So: upgrade Bun to 1.4.x (here, in the Dockerfile and in CI), re-run the probe, and the Browserbase adapter should work as written. Every provider in this document is reached with the same `connectOverCDP` call, so switching providers would not have fixed this.

## What Circle needs

From `src/tools/browser.ts` and `src/main.ts`: (1) a CDP websocket per session for `chromium.connectOverCDP`; (2) a persistent context so a person's cookies survive across sessions, with a `persist` flag; (3) a live view that embeds in an iframe so the person signs in inside the chat; (4) sessions that stay open about 15 minutes for that; (5) low cost at ~300 reads/day plus ~10 sign-ins/day, and a free tier for development. The adapter creates a fresh session per read, which matters below because most vendors bill a minimum per session.

## Per-provider notes

**Browserbase.** Plans: Free $0 (1 hr, 3 concurrent, 15-min max session, 7-day retention), Developer $20 (100 hr, $0.12/hr over, 6-hr max, 25 concurrent, 1 GB proxy then $12/GB), Startup $99 (500 hr, $0.10/hr, 100 concurrent, 5 GB proxy) (https://www.browserbase.com/pricing, https://docs.browserbase.com/account/billing/plans.md). Every session bills a minimum of one minute; session creation is rate-limited to 5/min on Free and 25/min on Developer (https://docs.browserbase.com/guides/concurrency-rate-limits). Max session duration 6 hours; set `timeout` in seconds at creation (https://docs.browserbase.com/platform/browser/long-sessions/timeouts.md). `keepAlive` is paid-only (https://docs.browserbase.com/platform/browser/long-sessions/keep-alive.md). Contexts persist cookies (including session cookies), localStorage, IndexedDB, service workers and preferences, saved only with `persist: true`; one context per site per login; do not run two sessions on one context at once; encrypted at rest; the docs do not say whether Free includes contexts [unverified] (https://docs.browserbase.com/features/contexts). Live view: `debuggerFullscreenUrl` from the debug endpoint, "Add the live view link to an iframe in your frontend", read-only by `pointer-events: none`, "delegate credentials - give control to the end user" is a listed use (https://docs.browserbase.com/features/session-live-view). Regions: us-west-2 default, us-east-1, eu-central-1, ap-southeast-1 via a `region` parameter (https://docs.browserbase.com/optimizations/latency/multi-region.md). Terms: no site-specific prohibitions; session recordings must keep their label and need "adequate data privacy" (https://www.browserbase.com/terms-of-service).

**Hyperbrowser.** Free: 5,000 credits, 1 concurrent session, 7-day retention, "must upgrade to continue" once spent; Startup $30/mo for 30,000 credits with 25 sessions, residential proxies and automatic captcha; Scale $100 for 100,000; browser time 100 credits/hr ($0.10), proxy 10,000 credits/GB ($10), 1,000 credits = $1 (https://www.hyperbrowser.ai/pricing, https://hyperbrowser.ai/docs/pricing.md). Sessions return a `wsEndpoint` for `chromium.connectOverCDP(session.wsEndpoint)`; `timeoutMinutes` min 1 max 720; `keepAlive=true` survives a disconnect but not closing every page; ultra stealth is enterprise-only (https://hyperbrowser.ai/docs/sessions/overview, https://hyperbrowser.ai/docs/sessions/playwright.md, https://hyperbrowser.ai/docs/sessions/lifecycle.md). Profiles "save and reuse browser state, which includes cookies, local storage, session storage, and cache"; `persistChanges: true` writes back, default false; "use the default browser context" with Playwright, which is what the adapter already does (https://hyperbrowser.ai/docs/sessions/profiles.md). Live view: `liveUrl` of the form `https://app.hyperbrowser.ai/live?token=…`, "You can embed Live View directly into your application using an iframe", interactive by default, `viewOnlyLiveView: true` for read-only, token valid 12 hours (https://hyperbrowser.ai/docs/sessions/live-view.md). Plan availability of profiles and billing granularity are not stated [unverified]. Regions not documented beyond proxy country.

**Browserless.** Monthly billing: Free $0 (1,000 units, 2 concurrent, 2-min max session, no overage), Prototyping $35 ($25 annual; 20,000 units, 5 concurrent, 15-min max, $0.002/unit over), Starter $200 ($140; 180k units, 30-min max), Scale $500 ($350; 60-min max) (https://browserless.io/pricing.md). "Every 30 seconds a browser session is open consumes 1 unit", rounded up, idle included; captcha 10 units per success; built-in residential proxy 6 units/MB (https://docs.browserless.io/overview/unit-consumption.md). Connect: `wss://production-sfo.browserless.io?token=…`, also `production-lon` and `production-ams` (https://docs.browserless.io/overview/connection-urls). Live URL is minted with the `Browserless.liveURL` CDP command, embeds in an iframe with `sandbox="allow-same-origin allow-scripts"`, `interactable:false` for view-only, five viewers per link, lifetime bounded by the session cap; hybrid automation is explicitly for "login flows, 2FA, CAPTCHAs" with a Done button (https://docs.browserless.io/baas/monitor-sessions/embedding-live-url.md, https://docs.browserless.io/baas/hybrid-automation). Authenticated profiles store cookies, localStorage and IndexedDB, capped at 2 MB and 50 origins, are loaded copy-on-write ("changes during the session stays local to that session and won't affect the original profile"), require `Browserless.saveProfile` to write, and profile-creation sessions have a 10-minute ceiling; Playwright must use `browser.contexts()[0]` (https://docs.browserless.io/baas/features/authenticated-profiles.md). Persisted sessions (`POST /session` with a required `ttl`, max 1 day Free / 7 days Prototyping) restore cookies and localStorage from disk per connection, one client at a time (https://docs.browserless.io/baas/session-management/persisting-state.md). Self-host image is "SSPL-1.0 OR Browserless Commercial License", commercial license needed to "build commercial sites, applications" (https://github.com/browserless/browserless).

**Steel.** Launch $0 + usage with $30 one-time credits, $0.10/browser-hr, $10/GB proxy, $3/1k captcha, 10 concurrent, 15-min max session; Scale $250 + usage, $0.08/hr, 1-hr max; Enterprise up to 24 h; GitHub 7.8k stars (https://steel.dev/pricing). Connect: `chromium.connectOverCDP(`${session.websocketUrl}&apiKey=${STEEL_API_KEY}`)` (https://docs.steel.dev/integrations/playwright). Default timeout 300,000 ms, minimum 15,000, maximum "set by your account limits", cannot be edited on a live session; billed by the minute; `inactivityTimeout` available (https://docs.steel.dev/overview/sessions-api/session-lifecycle, https://docs.steel.dev/overview/sessions-api/configuration). Profiles are "a snapshot of the browser's User Data Directory"; `persistProfile: true` on release, pass `profileId` to reuse, 300 MB cap, deleted after 30 days unused (https://docs.steel.dev/overview/profiles-api/overview). Live: every session returns a `debugUrl`, "Embed the session directly in your UI using an iframe", `interactive=false` for read-only, "Anyone with the debug URL can view or interact" (https://docs.steel.dev/overview/sessions-api/embed-sessions/live-sessions). Single region `us-east` (configuration page). Self-host: `ghcr.io/steel-dev/steel-browser:latest`, at least 4 GB RAM, ports 3000 and 9223, a Railway template exists; local is limited to 1 concurrent, no credentials, no captcha (https://docs.steel.dev/overview/self-hosting/docker, https://docs.steel.dev/overview/self-hosting/railway, https://docs.steel.dev/overview/self-hosting/steel-local-vs-steel-cloud).

**Kernel.** Developer: free + usage with $5 credits/mo, 5 concurrent, live view included; Hobbyist $30 + usage ($10 credits, 10 concurrent); Start-Up $200 + usage (150 concurrent, regions); usage $0.0000166667 per GB-second, no idle or proxy charge, headless default 1 GB, headful 8 GB (https://www.kernel.sh/pricing, https://kernel.sh/docs/info/pricing.md, https://kernel.sh/docs/browsers/concurrency-and-limits.md). Browsers are deleted after `timeout_seconds` (default 60, max 72 h) counted from standby, i.e. no CDP client and no live viewer; `browser.close()` does not delete (https://kernel.sh/docs/browsers/termination.md). Profiles capture the user-data directory, write back only with `save_changes` and only when the browser is deleted, single writer, encrypted per organization (https://kernel.sh/docs/browsers/profiles.md). Live view: `browser_live_view_url` in an iframe, `readOnly=true` or a `KERNEL_SET_READ_ONLY` postMessage, needs frame-src and connect-src in CSP (https://kernel.sh/docs/browsers/live-view.md). Regions `us-east` default, `eu-west`, `ap-southeast` on Start-Up and Enterprise (https://kernel.sh/docs/browsers/regions.md). The quickstart steers toward running Playwright inside the browser VM; the external CDP URL field name was not in the pages fetched [unverified]. Whether a 1 GB headless browser carries a usable live view for sign-in, or sign-ins need the $0.48/hr headful tier, is not stated [unverified].

**Browser Use Cloud.** No subscriptions; cloud browsers $0.02/hr billed in whole minutes with a 1-minute minimum; residential proxy $5/GB; $1 free once per person; $5 minimum top-up; a $100 lifetime top-up unlocks 50 concurrent (https://browser-use.com/pricing, https://docs.browser-use.com/cloud/guides/concurrency.md). Create a browser, read `cdpUrl`, `chromium.connectOverCDP(cdpUrl)`; "browser.close() and disconnecting CDP do not stop the managed browser", stop with `PATCH /api/v4/browsers/{id}` (https://docs.browser-use.com/cloud/browser/playwright-puppeteer-selenium.md). Live preview: `liveUrl` on live.browser-use.com, iframe, "Treat the URL as a credential"; view-only is "a UI restriction, not a server-enforced permission" (https://docs.browser-use.com/cloud/browser/live-preview.md). Profiles "persist cookies, local storage, and login state across browsers", one per end user, documented for V4 agent runs via `browserSettings.profileId`; use with a standalone CDP browser is not documented [unverified] (https://docs.browser-use.com/cloud/guides/authentication.md). Agent browsers have a 4-hour hard timeout; standalone browser lifetime not stated.

**Anchor Browser.** Free $5 credits/mo, 5 concurrent, US only, 7-day retention, and explicitly no "authenticated browsers"; Starter $50/mo; Growth $2,000; infrastructure usage $0.05/browser-hr to the nearest minute plus $0.01 per browser created, proxy $8/GB (https://anchorbrowser.io/pricing, https://docs.anchorbrowser.io/pricing.md). Session returns `id`, `cdp_url`, `live_view_url`; `chromium.connectOverCDP(session.data.cdp_url)` (https://docs.anchorbrowser.io/quickstart/create-session.md). Live view `https://live.anchorbrowser.io/inspector.html?sessionId=…`, iframe with sandbox and clipboard allow, read-only via `pointer-events: none`, `one_time_url` option (https://docs.anchorbrowser.io/advanced/browser-live-view.md). Timeouts: `idle_timeout` default 5 min, `max_duration` default 180 min (https://docs.anchorbrowser.io/advanced/session-timeout.md). Profiles persist cookies, local storage and cache; "Identities" store credentials and re-authenticate, which is the thing Circle chose not to do (https://docs.anchorbrowser.io/essentials/managed-authentication.md).

**Lightpanda.** AGPL-3.0 headless engine with "No graphical rendering engine" (https://github.com/lightpanda-io/browser). Cloud: Explorer free 10 hr/mo, 5 concurrent; Builder $19/mo, 300 hr, $0.08/hr over (https://lightpanda.io/pricing). Connect `wss://uswest.cloud.lightpanda.io/ws?token=…`; `browser=chrome` runs real Chrome but "Chrome isn't intended for production traffic"; a CDP connection closes after 15 minutes (https://lightpanda.io/docs/run-on-lightpanda-cloud/getting-started, https://lightpanda.io/docs/run-on-lightpanda-cloud/limits-and-billing). No screenshots, no live view, no profiles.

**Proxy Human.** Not a browser host. The MCP "needs CDP access to a local Chrome and a local ffmpeg", screencasts it to Cloudflare Realtime and mints a viewer link with `open_browser_handoff_link`; v0.4.0 published 2026-05-20 (https://registry.npmjs.org/@proxyhuman/mcp, https://proxyhuman.ai/). Free: 2 human-connected hours/mo, sessions up to 5 minutes; Pro $15/mo, 24 hours, 60-minute sessions; metered only while a human is connected (https://proxyhuman.ai/pricing). Relevant only as a live-view layer over a self-hosted Chrome, and the 5-minute free cap is below our sign-in window.

**agentweb.** "Web access CLI for AI agents: search, fetch, extract, and source-pack"; 12 free search providers, trafilatura then Jina Reader then optional Camoufox; MIT, 13 stars, no hosted service, no CDP (https://github.com/thanhan-a17/agentweb). It overlaps `JinaReader`, not Browserbase.

**simular.ai list.** Named Sai (a desktop agent, not a browser API), Steel, Browser Use, Kernel, Anchor, Hyperbrowser, Lightpanda, Browserless, Bright Data (sessions "limited to one domain", $8/GB; not pursued) and Apify (actor marketplace; not a browser host) (https://www.simular.ai/alternatives/browserbase-alternatives). The figures it quotes matched the vendors' pages except Steel's free-tier framing (it is $30 of one-time credit, not a free plan).

**Self-hosted.** Fly Machines in ewr: shared-cpu-1x 1 GB $6.70/mo, shared-cpu-2x 2 GB $13.39, 4 GB about $25.40, extra RAM $6/GB, stopped machines $0.15/GB rootfs, no free tier for new orgs (https://docs.fly.io/about/pricing). Railway: Hobby $5/mo with $5 credit, then about $0.0278/vCPU-hr and $0.0139/GB-hr, so a 1 vCPU / 2 GB container always on is roughly $40/mo plus the plan (https://railway.com/pricing). Note the memory file says the Fly app is retired and Railway is the intended host, so price for Railway. The Steel image gives the same session/profile/debugUrl shape as Steel Cloud under Apache-2.0 (the browserless image is SSPL and needs a commercial licence for a commercial app). What self-hosting adds to our plate: a public `wss://` endpoint, our own auth in front of the live view (Steel's `debugUrl` is unauthenticated), encrypted cookie storage on a volume, Chrome memory headroom, and nobody else's stealth or proxies.

## Cost at Circle's volume

Assumptions: 300 reads/day of 20 s each (1.7 browser-hr/day, 50 hr/mo) and 10 sign-ins/day of 10 min (50 hr/mo). Real usage is 100 hr/mo; with a 1-minute minimum per session the 300 reads bill as 150 hr/mo, so 200 hr/mo.

| Provider | Monthly cost | Note |
|---|---|---|
| Browserbase | $32 (Developer $20 + 100 hr × $0.12) | 1-min minimum; $20 if reads share sessions. Free plan covers one hour a month: development only |
| Hyperbrowser | $30 (Startup) | 100–200 hr = 10,000–20,000 of 30,000 credits; the free 5,000 credits last about two weeks at this rate |
| Steel | $20 (Launch, pay as you go) | per-minute billing, so 200 hr × $0.10; the $30 credit covers the first six weeks |
| Kernel | $6–30 | 200 hr headless × $0.06 = $12 if live view works headless; if sign-ins need headful, 50 hr × $0.48 = $24 more; $5/mo credit offsets |
| Browser Use Cloud | $4 | 200 hr × $0.02; only if profiles work on standalone browsers [unverified] |
| Browserless | $35 (Prototyping) | 300 reads × 1 unit + 10 sign-ins × 20 units = 500 units/day, 15,000/mo of 20,000; free plan's 2-min sessions cannot host a sign-in |
| Anchor | about $100+ | 310 browsers/day × $0.01 creation = $93/mo before browser time, plus Starter $50 for authenticated browsers |
| Self-hosted Steel | $13–25 on Fly, about $45 on Railway | flat; plus our time |

The cheapest lever is not the vendor: do anonymous reads on the server's local Chrome or Jina (already in the chain) and only send `contextId` reads and sign-ins to the hosted browser, and reuse one session for consecutive reads inside a run. That halves hosted hours and removes most of the 1-minute minimums, which brings Browserbase to its $20 floor.

## What to take, ranked

1. **Fix the runtime, keep Browserbase.** Upgrade Bun to 1.4.x (local, Dockerfile, CI), rerun the connect probe, and the existing adapter works: Contexts and the live view match `startSignIn`/`finishSignIn` one for one, regions include eu-central-1 and ap-southeast-1 for later households, and Developer is $20/mo. The free plan's 15-minute session cap is exactly the `timeout: 900` the adapter asks for, but one hour a month makes it development-only; expect to pay $20 when the first real household signs in.
2. **Add Hyperbrowser as the fallback for signed-in work.** Same shape as Browserbase: session with `wsEndpoint`, profile with `persistChanges`, `liveUrl` in an iframe with a `viewOnlyLiveView` flag, sessions to 720 minutes, and 50 free hours to build it. An adapter is a copy of `BrowserbaseBrowser` with four URL changes. The `FallbackBrowser` chain already routes sign-ins to the first provider that offers one; add a second signer only if we want sign-ins to fail over too.
3. **Cut hosted usage in the adapter before cutting vendors.** Route anonymous reads to local Chrome/Jina, hold one session across the reads of a run, and release promptly. This matters on every vendor with a per-session minimum (Browserbase, Steel, Browser Use) or a 30-second unit (Browserless).
4. **Steel is the self-host answer when it is time.** Apache-2.0, the same session/profile/debugUrl API in cloud and in the container, a Railway template, and per-minute pay-as-you-go cloud if we want Steel Cloud without self-hosting. Not before households justify running Chrome ourselves.
5. **Watch Browser Use Cloud and Kernel.** Browser Use is five times cheaper than anyone, but profile use on a standalone CDP browser is undocumented and the read-only live view is client-side only. Kernel's no-idle billing and encrypted profiles are good engineering; the headless-vs-headful question for the sign-in view and regions-on-$200-only keep it a watch.
6. **Skip** Browserless (2-minute free sessions, copy-on-write profiles that need a separate save step, SSPL image), Anchor (per-browser creation fee, authenticated browsers paid-only, and "Identities" that store credentials), Lightpanda (no rendering, so no live view or screenshots), Proxy Human (a viewer over a local Chrome, 5-minute free sessions), agentweb (a search CLI, not a browser), Bright Data (one domain per session).
