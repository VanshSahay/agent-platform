# Super.com hotel pricing: what the site calls (22 Oct 2026)

Observed in Ellie's signed-in Chrome on the Courchevel search (13–18 Jan 2027, 2 adults) and the Alpes Hôtel du Pralong page. A headless Chrome got Cloudflare's Turnstile challenge on both pages and never reached the app (REA capture ev_924d0e3f…), so everything below is from the real browser's network log and the page's router state.

## The API

One tRPC gateway, unauthenticated, GET with a URL-encoded JSON `input`:

`https://www.super.com/snapcommerce/api/trpc/<procedure>?input=<json>`

Search is a job, not a single call:

1. `recommender.getUnauthMapView` with `queryParams: { region_id: 98238, checkin_at, checkout_at, num_adults, children: "[]", country_code: "US", currency: "USD", locale: "en-US", platform: "Web", page: 1, page_size: 25, user_properties: "region_code_from_ip=NY&country_code_from_ip=US" }` and a `deviceId` (a UUID the client mints). It returns a job id of the form `hss-lds:<uuid>` ("hotel search service").
2. `recommender.checkJobStatus` with `pathParams.jobId`, polled four times here.
3. `recommender.getUnauthMapViewByJobId` returns `result.data.query_results[]`, one entry per hotel: `{ hotel, rate, retail_rate }`.

The hotel detail page is server-rendered through TanStack Router; its loader carries `hotel`, `rateCalendar`, `guestRating`, `guestReviews`, `bookingTrends`, and the only extra calls are `recommender.getHotelReviews` and `getUnauthMapViewByJobId` for the map. The booking page (`/travel/booking?prebookId=…`) is the step after.

## The rate object (Pralong, 5 nights)

```
nightly_price_before_tax 1189.86   nightly_total_price 1392.19   currency USD
num_nights 5   num_rooms 1   surcharge 44.5   tax_on_surcharge null
bar_price 7921.59   bar_price_before_tax 6770.33
is_mor true   is_superplus_rate false   is_superplus_eligible true
retail_rate null
```

Total shown on the site: `nightly_total_price × num_nights + surcharge` = 1392.19 × 5 + 44.5 = **$7,005.45**, displayed as $7,008 (rounding on their side). Taxes and fees are 17% of the pre-tax nightly rate; Google's ladder estimated 10%, which is why Google listed Super.com at $6,498 for the same room. `bar_price` is the "was $1,380/night" strike-through; `is_mor` means Super.com is merchant of record; `is_superplus_rate` marks the paid-membership rate (not applied here).

## Where the inventory comes from

No supplier field is exposed. Two signals: hotel images are served from `i.travelapi.com/lodging/…`, Expedia Partner Solutions' image host, so the beds are Expedia Rapid inventory; and `review_data` carries `priceline_rating` and `priceline_review_count`, so Priceline supply is in the mix. The Google click-through for this rate carried `provider=htl&provider_hotel_id=10004666061`, their internal provider code.

## What this means for Circle

- Super.com's checkout total is the all-in figure; Google's "with taxes" is an estimate that can be short by the seller's own fee and tax treatment. The comparison page says so.
- Calling this API from the server is not worth it: it is Super.com's private app API behind Cloudflare Turnstile and a device id, and reading it from a datacenter would be both fragile and against their terms. If a single hotel's checkout price is ever needed, a Browserbase read of the hotel page and `nightly_total_price × num_nights + surcharge` from the router state is the formula.
